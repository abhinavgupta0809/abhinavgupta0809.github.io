More detail

Plain-English questions about statements, invoices, pay stubs and 1099s; the data never leaves your computer. Scope by decision: no bank linking, no advice, synthetic data only. Built with AI coding tools in weekly syncs with the co-founder. Cent Capital now owns the code, open-sourced under Apache-2.0, and credits me as the original author.

I built the evals first: a golden dataset, two retrieval metrics and a gate that fails the build

Every change ran against the same 80-question golden dataset before it could ship, and every run was pinned to the exact code, settings and data that produced it.

Golden dataset written by me; the AI judge was checked against 20 human labels.

More detail

Recall@20 asks whether the right source appears anywhere in the top 20 results; MRR asks how high it ranks, so 1.0 means first every time. Hybrid search plus a reranker took recall@20 from 0.96 to 0.98 and MRR from 0.50 to 0.79. The AI judge is a small check on 20 labels, so the retrieval numbers, which need no judge, are the ones to lean on.

I rejected my own changes when they missed the bar

Six local models, a new prompt and a citation checker each ran against gates set in advance. Only the model already in use held.

Right source in the top 20 results 98% of the time; all 6 planted data leaks blocked

The scorecard the gates were set against: retrieval quality on the golden dataset, and guardrails on planted attacks.

An agent with calculator and SQL tools did better on cross-document totals with the 8B model (17% to 58%, on just 12 questions) and worse with the smaller 4B model. The shipped product uses hybrid search.

A null result, written up

Six temperature and top-p settings against the baseline: all seven passed the same strict rows. A null on this task and corpus, with one seed and one model, not a claim that decoding never matters.
